# Serde for MoonBit

Add `#custom.serde` to a struct or enum to generate MoonBit `ToJson` and `@json.FromJson` implementations before compilation. The generator reads and constructs the official [MoonBit AST](https://github.com/moonbitlang/parser), then formats the AST as source. The generated code uses normal trait calls and does not need reflection, a compiler plugin, or a language server.

## Usage

Put these declarations in `src/models.mbt`:

```mbt nocheck
///|
#custom.serde(rename_all="camelCase")
struct Profile {
  display_name : String
  #custom.serde(skip_serializing_if="Option::is_none")
  avatar_url : String?
}

///|
#custom.serde(tag="type", content="data", rename_all="snake_case")
enum Delivery {
  Pending
  Sent(Profile)
}
```

With the [build rule](#setup) in place, call the standard JSON traits. This example reads an explicit `null` as `None`, then omits that field when it writes JSON:

```mbt nocheck
///|
fn main {
  let input : Json = {
    "type": "sent",
    "data": { "displayName": "Aki", "avatarUrl": null },
  }
  let delivery : Delivery = try! @json.from_json(input)
  println(ToJson::to_json(delivery).stringify())
}
```

```json
{"type":"sent","data":{"displayName":"Aki"}}
```

## Setup

Use MoonBit `0.1.20261117` or a compatible toolchain with `moon.mod`, `moon.pkg`, and `dev_build`. The generator is a native executable. The generated codecs can run on other targets.

1. Clone this repository next to your module. From the Serde checkout, run `nix profile install .#serde-gen`. Make sure your Nix profile's `bin` directory is on `PATH`. To try the command without installing it, run `nix run .#serde-gen -- --help`.
2. In the parent directory, add both modules to `moon.work`. Use the actual directory names:

   ```mbt nocheck
   members = [ "./my-app", "./serde" ]
   ```

3. Add `"totto2727/serde@0.1.0"` to the `import` block in your module's `moon.mod`. This package is not published on Mooncakes. The workspace resolves the dependency from the checkout.
4. In the `moon.pkg` of the package that defines the types, add these imports and a [pre-build rule](https://docs.moonbitlang.com/en/latest/toolchain/moon/package.html#rule-and-dev-build):

   ```mbt nocheck
   import {
     "moonbitlang/core/json",
     "totto2727/serde",
   }

   rule(name: "serde", command: "serde-gen $input --output $output")
   dev_build(rule: "serde", input: "models.mbt", output: "models.generated.mbt")
   ```

5. Run `moon check`, `moon build`, or `moon test` in your module. Moon writes the `.generated.mbt` file in the package that defines the types. Do not edit this file. If another module consumes your package as a dependency, include the file in the source you distribute. Moon does not execute dependency `dev_build` rules.

To generate without a build rule, run `serde-gen INPUT... --output OUTPUT`. The inputs must belong to the same MoonBit package. Write the output to that package and import `@json` and `@serde` there. After you update the generator, run this command again or remove the output file so Moon generates it again.

### Generate a package without listing files

Run `serde-gen --package src/models` before your `moon` command, for example `serde-gen --package src/models && moon check`. Use this command **instead of** a `dev_build` rule for the same codecs. It writes `src/models/serde.generated.mbt` and updates it after a source is added, changed, or removed. An unchanged result is not rewritten.

Package mode scans ordinary `.mbt` files in that directory, without traversing child packages. It skips generated files ending in `.generated.mbt`, test files, and backend-suffixed files. Use the explicit-input form and configure a matching output for declarations enabled only on some targets, including files made target-specific by `moon.pkg`.

Only files that contain the literal `#custom.serde` marker are parsed. The official parser confirms the attribute, so a comment or a string alone cannot generate a codec. Moon's `dev_build` uses concrete file dependencies: a wildcard is not expanded, and using the directory as an input does not detect edits to existing files. Put the package command before `moon` in your task runner to avoid stale codecs without listing filenames.

## JSON representation

### Struct fields

Structs use JSON objects. An optional field (`T?` or `Option[T]`) reads a missing or `null` value as `None`. `Some(value)` writes the inner value without a wrapper. `None` writes `null` unless `skip_serializing_if="Option::is_none"` omits the field.

| Attribute argument | Applies to | Behavior |
| --- | --- | --- |
| `rename="new_name"` | Field, variant | Read and write the given name. |
| `path=["part", "state", "status"]` | Struct field | Read and write the field at a fixed sequence of JSON object keys. |
| `aliases=["old_name"]` | Field | Also read each alias. A payload with more than one accepted name for the field is an error. |
| `default` | Field | Use the type's `Default` value when the field is absent. An explicit `null` still goes to the field's decoder. |
| `skip` | Field | Do not write or read the field. Restore `None` or the type's `Default` value. |
| `skip_serializing_if="Option::is_none"` | Optional field | Omit `None` instead of writing `null`. |
| `deny_unknown_fields` | Struct | Reject keys that do not identify a field. |
| `rename_all="camelCase"` | Struct, enum | Rename struct fields or enum variant tags. `rename` takes precedence. |

The `rename_all` values are `lowercase`, `UPPERCASE`, `PascalCase`, `camelCase`, `snake_case`, `SCREAMING_SNAKE_CASE`, `kebab-case`, and `SCREAMING-KEBAB-CASE`.

#### Fixed object paths

Use `path` when the MoonBit struct is flat but the JSON fields are nested. This struct reads and writes `{"part":{"state":{"status":"completed"}}}`:

```mbt nocheck
///|
#custom.serde
struct ToolEvent {
  #custom.serde(path=["part", "state", "status"])
  status : String
}
```

Each string is one literal object key. Dots, slashes, and digits inside a key do not change its meaning. A path must have at least one key and cannot use array indices. A path overrides `rename_all` for the field and cannot be combined with `rename` or `aliases` on that field.

Fields can share parent objects, but a field path cannot duplicate another path or be its prefix, including a flat field name or alias. On write, parent objects are created as needed, and omitting a field does not create an empty parent for it. On read, a missing parent or leaf uses the field's usual missing-value rule. A present parent must be an object, even for an optional field. Errors point to the first missing or invalid segment. `deny_unknown_fields` also checks the objects created by path prefixes. Values stored at leaf paths use their own decoders.

The Option rule applies to fields and variant arguments declared directly as `T?` or `Option[T]`, including nested Options. `None` and `Some(None)` both write `null` and read back as `None`. The first non-Option type uses its own JSON traits. For example, `Array[T?]` uses MoonBit's standard Option representation for its elements.

### Newtypes and tuple structs

Annotate a tuple struct with `#custom.serde`. A single element is encoded directly, so `struct Distance(Int)` reads and writes `12`. A tuple struct with multiple elements such as `struct Measurement(Distance, String?)` reads and writes a fixed-length JSON array such as `[12,"m"]` or `[12,null]`.

Elements follow declaration order. An optional element still requires its array slot; use `null` for `None`. Tuple structs accept `decode_only`, but not options for named fields or enum tags.

### Enums

| Representation | Enum attribute | Unit variant `Idle` | Payload variant |
| --- | --- | --- | --- |
| External tag | `#custom.serde` | `"Idle"` | `{"Text":"hello"}` |
| Internal tag | `#custom.serde(tag="type")` | `{"type":"Idle"}` | `{"type":"Named","text":"hello"}` |
| Adjacent tags | `#custom.serde(tag="type", content="data")` | `{"type":"Idle"}` | `{"type":"Text","data":"hello"}` |
| Untagged | `#custom.serde(untagged)` | `null` | `"hello"` |

A single positional argument writes its value. Multiple positional arguments write a JSON array. Labeled arguments write a JSON object. Internal tagging supports unit and labeled variants. An untagged enum reads with the first variant that decodes successfully, in declaration order. Use a tagged representation when multiple variants accept the same value.

Add `decode_only` to a struct or an enum to generate only `@json.FromJson`. An internally tagged enum with `decode_only` can also have variants with one non-optional positional payload. The payload decoder receives the original object, including the tag, at the original JSON path. Use a payload decoder that accepts that object, including its tag field.

## Errors

Generation errors identify the source file and range. For example, an empty `path` on a field can produce `models.mbt-3:3-4:14: path must be a non-empty array of string keys`. A duplicate annotated type reports both definitions.

At runtime, `@json.JsonDecodeError((path, message))` contains a JSON Pointer and a reason. For example, a missing `part` object yields `/part` and `missing field: part`, instead of pointing to the absent leaf `/part/state/status`. When no untagged variant matches, the message lists each variant, its JSON Pointer, and its reason.

## Scope

This package generates JSON codecs for record structs, tuple structs (including newtypes), and enums, with or without named type parameters. The generated encoder uses `ToJson`; the decoder uses `@json.FromJson`. A skipped field needs no JSON trait. For generic types, the generator adds a bound for the relevant direction to parameters used by serialized fields, and adds a `Default` bound for parameters in non-optional fields initialized with `default` or `skip`. Do not derive traits that `#custom.serde` generates for the same type. The generator does not implement Rust Serde's format-independent traits, custom hooks, or flattening.
